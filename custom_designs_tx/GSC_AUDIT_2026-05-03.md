### SPA / JavaScript Rendering — CRITICAL CONFIRMED

Both the homepage and the blog post (`/blog/security-camera-installation-mcallen-tx`) return page **titles** when fetched, but the WebFetch tool confirms these are JavaScript-rendered titles from the `<head>` — the body remains `<div id="root"></div>`.

**What Google CAN see (static HTML):**
- `<title>` tags (page-specific)
- `<meta name="description">` tags
- `<link rel="canonical">` tags
- JSON-LD schema blocks in `<head>`
- Open Graph tags

**What Google CANNOT see without JavaScript execution:**
- All H1, H2, H3 headings
- All body copy / article text
- Internal navigation links
- Service descriptions
- Location-specific content
- Blog article content

**Verdict: BLOCKER #1 CONFIRMED.** The SPA architecture makes all 60 sitemap pages effectively empty to Googlebot's first-pass crawl. The only search visibility Custom Designs has is from Google's delayed JavaScript Wave renderer (days-to-weeks delay, resource-constrained, unreliable for ranking purposes).

- Setup: add Prerender middleware to `vercel.json`, set `PRERENDER_TOKEN` env var
- Estimated time to implement: 2-4 hours

**Option B — Vite SSG (Free, requires dev work):**
- Add `vite-plugin-ssg` or migrate to Astro for blog and service pages
- Full static generation at build time
- Better long-term solution but requires 1-2 days of development work
- The Lovable.dev platform may limit what can be modified in the build pipeline

**Option C — Next.js migration (Best for SEO, 1-2 week project):**
- Migrate the site from Lovable.dev/Vite/React to Next.js with SSR/ISR
- Blog pages use `getStaticProps` for full static HTML at build time
- Best long-term solution but significant migration effort
- Vercel natively supports Next.js SSR with zero configuration

**Recommendation:** Start with Option A (Prerender.io) immediately for quick wins while evaluating Option C as the long-term play.
