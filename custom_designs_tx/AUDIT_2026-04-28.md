# Custom Designs TX — Root Cause SEO Audit
**Date:** 2026-04-28  
**Auditor:** Claude Code (Antigravity Digital)  
**Sources verified:** Live WebFetch (customdesignstx.com), keyword_rankings_state.json, gbp_state.json, seo_optimizer_state.json, gsc_token.json, blog_posts meta files, sitemap.xml, robots.txt  
**Scope:** Technical health, GSC, GBP, indexing, ranking data, Mission Control accuracy

---

## Executive Summary

1. **The website is a pure client-side React SPA with zero crawlable body content.** Every page returns a 5–6 KB HTML shell with `<div id="root"></div>` as the only body element. Googlebot's crawler cannot see any page text at all without JavaScript rendering. This is the single largest ranking blocker.

2. **GSC is disconnected — the OAuth token expired 2026-04-18 and has not been refreshed.** No current GSC data exists. All Mission Control ranking "impressions" figures are unverified and potentially stale. The GSC account field is also blank, meaning we cannot confirm which property is verified.

3. **Zero organic map-pack positions on 54 of 56 tracked keywords.** The one GBP appearance (map position 3 for "smart home installation mcallen" on 2026-04-25) is encouraging but isolated. Competitors D-Tronics (225+ reviews), RGV Spy Tek, Texas Security Systems (106+ reviews), and Vivint (300+ reviews) dominate the local pack. Custom Designs has 7 reviews at 5.0 stars — a severe authority gap.

4. **6 of 10 generated blog posts have never been published to the website.** The location-targeted posts (Edinburgh, Mission, Harlingen, Pharr) were marked `website: true` in meta files but were generated on 2026-03-27 and may not have been pushed to the repo/Vercel. The CCTV, surround sound, and alarm posts return 404.

5. **One canonical URL is broken (`https://www.customdesignstx.comundefined`) on the Pharr blog post**, and two duplicate LocalBusiness schemas appear on every page with conflicting priceRange values (`$$` vs `$`). Both signal quality issues to Google.

### 1.4 SPA / JavaScript Rendering — CRITICAL FINDING

**Verified via Googlebot user-agent fetch of raw HTML source.**

Every page on customdesignstx.com — homepage, service pages, blog posts, community pages — returns an HTML shell of **5,000–6,200 bytes** with this body:

```html
<body>
  <div id="root"></div>
  <!-- IMPORTANT: DO NOT REMOVE THIS SCRIPT TAG OR THIS VERY COMMENT! -->
  <script src="https://cdn.gpteng.co/gptengineer.js" type="module"></script>
</body>
```

**Zero body text is in the HTML.** All content is injected client-side via `index-I9UBzyNE.js`.

What Google CAN see in the static HTML:
- `<title>` tag (page-specific, correctly set per route)
- `<meta name="description">` (page-specific)
- `<link rel="canonical">` (mostly correct, one broken — see 1.6)
- JSON-LD schema (2–3 per page, embedded in `<head>`)
- Open Graph tags

What Google CANNOT see without JavaScript execution:
- **All H1, H2, H3 headings**
- **All body copy / article content**
- **Internal navigation links**
- **Any service descriptions**
- **Any location-specific content**

**Googlebot does attempt to render JavaScript** (it uses a headless Chrome-like renderer called "Wave"), but rendering is:
1. Queued with significant delay (days to weeks after first crawl)
2. Resource-constrained — complex React apps are often partially rendered
3. Not reliable for indexing meaningful content vs. a static HTML page

**Platform:** Lovable.dev (React + Vite + TypeScript) deployed on Vercel. This is confirmed by program.md and `cdn.gpteng.co` script tag.

**Status of pre-rendering/SSR:** None detected. The site does NOT use Vercel's SSR features or any static site generation. The `vercel.json` SPA fix mentioned in program.md (pushed 2026-03-18) solved the routing 404 problem but did not address the rendering problem.

### 1.5 Schema Markup

**Blog page example (`/blog/security-camera-installation-mcallen-tx`) — 3 JSON-LD schemas found:**

1. `LocalBusiness` (schema 1): priceRange `$$`, correct address, phone, hours — **DUPLICATE**
2. `LocalBusiness` (schema 2): priceRange `$` — **DUPLICATE with conflicting data**
3. `Article`: headline, description, datePublished `2026-01-19`, dateModified `2026-04-02` — correct type but datePublished is wrong (actual publish date was 2026-03-18)

**Homepage — 2 JSON-LD schemas:**
1. `LocalBusiness`: priceRange `$$`
2. `LocalBusiness`: priceRange `$` — DUPLICATE, conflicting priceRange

**Issues:**
- **Duplicate LocalBusiness schemas on every page** — Google sees two contradictory declarations.
- **No `Service` schema** on service pages — a missed signal for service-type queries.
- **No `BreadcrumbList` schema** — zero breadcrumb signals.
- **`datePublished` is wrong** on the security camera blog post (2026-01-19 vs actual 2026-03-18).
- **No `FAQPage` schema** — common on competitor service pages, missed opportunity.

### 1.6 Canonical Bugs

**Pharr blog post (`/blog/security-camera-installation-pharr-tx`):**
```html
<link rel="canonical" href="https://www.customdesignstx.comundefined" />
```

This is a broken canonical. Google will not know the correct canonical URL for this page, potentially causing it to be deindexed or treated as a duplicate. The `og:url` also contains `undefined`.

**Root cause:** A code bug in the static blog router where the slug was not resolved before being appended to the base URL.

### 1.7 Core Web Vitals / Performance
- **HTML payload:** 5,000–6,200 bytes (very small — fast TTFB).
- **Blocking:** All content is deferred behind one `index-I9UBzyNE.js` bundle plus `cdn.gpteng.co/gptengineer.js`. Both must load and execute before any content is visible.
- **LCP (estimated):** Will be poor due to no above-the-fold static content. LCP cannot occur until JS executes.
- **CLS:** Unknown without rendering.
- **INP:** Unknown.

### 1.8 OTTO SEO (SearchAtlas Dynamic Optimization)
The site uses SearchAtlas Dynamic Optimization (`dashboard.searchatlas.com/scripts/dynamic_optimization.js`) with UUID `82c74bcd-de0e-4270-bed4-8fbe3da9e42e`. This is a client-side SEO tool that likely dynamically modifies meta tags and potentially headings. **However:** since the base HTML already has correct meta tags in the `<head>`, and since the body content is client-rendered anyway, this tool's benefit is limited unless it is also handling content injection for crawlers. Its presence is noted but does not solve the core SPA crawlability problem.

## Section 6 — Root Cause Diagnosis

### Root Cause #1: SPA Architecture = Googlebot Cannot Read Content (CRITICAL)
**Type:** Technical / Indexing problem  
**Evidence:** Raw HTML fetch (Googlebot user-agent) confirms `<div id="root"></div>` body. HTML is 5,000–6,200 bytes. All 71 sitemap URLs have identical structure. No SSR, no static generation, no prerendering.  
**Impact:** Google's Wave renderer *may* eventually crawl and render some pages, but:
- Rendering is delayed by days to weeks per URL
- 71 URLs x rendering budget = very slow coverage
- JavaScript-rendered content ranks significantly worse than server-side HTML
- React hydration requires `cdn.gpteng.co/gptengineer.js` to also load, adding a second dependency
- This explains why organic rankings are sporadic (position 9 once, then gone)

**Fix required:** Enable Vercel SSR or static generation (SSG/ISR) for all routes, OR migrate to a server-rendering approach (Next.js, SvelteKit, Astro). Alternatively, add a pre-rendering layer via Prerender.io or Vercel's built-in SSG export.

### Root Cause #2: GBP Authority Gap — 7 Reviews vs. 54–300+ Competitors (SEVERE)
**Type:** Authority / GBP problem  
**Evidence:** Custom Designs has 7 reviews. The top 5 map pack competitors have 54, 106, 225, 159, and 300+ reviews respectively. D-Tronics alone appears 221 times in the local map pack across all tracked keywords.  
**Impact:** Google's local ranking algorithm treats review count and recency as a primary trust signal. At 7 reviews, the listing cannot compete for competitive head terms. The single map-pack appearance at position 3 for "smart home installation mcallen" (a slightly less competitive query) confirms the listing is functional but under-authorized.  
**Fix required:** Active review acquisition campaign. Target: 20+ reviews in 60 days. GBP post cadence should be 1–2x/week minimum (last post was 40 days ago).

### Root Cause #3: 4 Blog Posts Are 404 and GSC Is Blind (HIGH)
**Type:** Content deployment + reporting problem  
**Evidence:** `/blog/cctv-installation-mcallen-tx`, `/blog/surround-sound-installation-mcallen-tx`, `/blog/home-theater-surround-sound-mcallen`, `/blog/alarm-system-installation-mcallen-tx` all return HTTP 404. The blog_writer pipeline generates `.md` files but does not push them to the GitHub repo (the Lovable.dev site source) automatically. Additionally, GSC token expired 2026-04-18 — no impressions, click, or coverage data has been collected since.  
**Impact:** Content creation investment is wasted if it never deploys. The GSC blind spot means we cannot even verify what's happening with the 6 live posts.  
**Fix required:** Establish a deployment workflow: blog_writer → push to GitHub repo → Vercel auto-deploys. Re-authenticate GSC immediately.

### Root Cause #4: Canonical Bug + Duplicate Schema on Every Page (MODERATE)
**Type:** Technical / Relevance problem  
**Evidence:** `/blog/security-camera-installation-pharr-tx` has canonical `https://www.customdesignstx.comundefined`. Every page has two LocalBusiness schemas with conflicting priceRange. Blog post Article schema has wrong datePublished.  
**Impact:** The broken canonical tells Google there is no authoritative URL for the Pharr page — it may not be indexed or may be treated as duplicate content. Duplicate schemas create ambiguity.

### Root Cause #5: Zero Facebook Organic Reach (LOW-MEDIUM)
**Type:** Social proof / GBP signal problem  
**Evidence:** All 10 blog posts have `facebook: false`. D-Tronics posts installation videos weekly on Facebook with 272 views per post (video format). Mach 1 Media shows real job footage getting 297 views. Custom Designs has 0 Facebook content.  
**Impact:** Facebook is not a direct ranking factor, but consistent social posting drives branded search, GBP clicks, and review velocity — all of which are ranking factors.
